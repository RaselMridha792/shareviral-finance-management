## 1. AI tools & subscriptions: "Renews on" can be edited

**The owner, 26 Oct:** a plan started on 30/06/2026, billed monthly, shows **Renews on
30/10/2026**. The app counts on from today, so a plan entered from past data gets a renewal
date that never happened. They want it filled in as now, and editable.

*"autofill system ta thik thakuk choto ekta adjustment kore daw … renew month tao edit kora jay
eta auto fill hobe thik ache kintu eta ami edit o korte parbo"*

**What is there today:**
- `subscriptionFieldsSchema` (`packages/shared/src/subscriptions.ts`) deliberately has **no
  `nextRenewalOn`**. It is worked out by `nextRenewalAfter(start, cycle, …)`, and after that it
  moves only when a payment is recorded. A sent `nextRenewalOn` is refused by name.
- The form shows the derived date read-only.

**What the owner wants:**
- **The box.** "Renews on" on Add a plan and on Edit becomes a real date box.
  - It is prefilled with the derived date, the same as now.
  - Typing over it keeps the typed date.
  - Clearing it puts the derived date back.
- **The API.** `nextRenewalOn` comes back as an optional field on create and update.
- **What stays.** Recording a payment still rolls the date forward, as it does today.

**Points to check:**
- This touches `packages/shared`: the shared-code rule applies, and it needs a rebuild.
- The Assistant's map (`subscriptions/app-map.ts`) says the date is derived, and has to change.
- For past data, the plans imported on live carry derived dates. Should they be corrected? Ask
  the owner: by hand, or from each sheet row's "Next Renewal Date", which the import has in
  `boss.json`.

## 2. AI tools & subscriptions: Invoice and Reference take several files at once

**The owner, 26 Oct:** when editing a plan, picking several papers for Invoice or Reference
keeps only one. A second paper means saving, opening the plan again and picking it there. It
comes up most when correcting old data.

**Why it happens.** Read in the code, not yet run:
- `subscription-form.tsx` has its own picker for each slot. It is `<input type="file">` without
  `multiple`, and it keeps `event.target.files?.[0]`: **one `File | null`** per slot
  (`invoiceFile`, `referenceFile`).
- On save it uploads at most one of each.
- The shared `AttachClip` (`components/files/attach-clip.tsx`) already takes several files, with
  `multiple` and a list of additions. Cash In, the ledger form and Money Transfer use it. The
  plan form never moved onto it.

**What to do:**
- Give the plan form's Invoice and Reference the same several-at-a-time behaviour:
  - preferably by using `AttachClip`;
  - otherwise by holding a list in each slot and uploading each file on save.
- **What stays as it is:**
  - the papers already on file still show, and can be removed;
  - the same paper picked twice is still refused;
  - Cancel still changes nothing.
- **Measure it.** Open an existing plan, pick two invoices and two references at once, and save.
  All four are on file, and the register's columns count them.
